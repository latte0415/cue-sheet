# MCP 서버 (`/mcp`) — 에이전트로 큐시트 고치기

Claude Code·Codex 같은 AI 에이전트가 사이트의 큐시트를 **읽고 일부만 고칠 수 있게** 하는 원격 MCP 서버.
"3번 씬 끝에 박대훈 퇴장 큐 넣어 줘", "BGM 3 을 5번으로 바꿔 줘", "아까 수정 되돌려 줘" 같은 요청을 에이전트가 처리한다.
구현은 `lib/mcp.js`(도구), `lib/ops.js`(수정 적용), `lib/view.js`(개요·검색), `lib/labels.js`(큐 번호), `lib/store.js`(저장·기록),
`lib/tokens.js`(사람별 토큰).

## 연결하기 (개발자가 아니어도 됨)

필요한 것: 사이트 주소(예: `https://cue-sheet.example.app`), **내 토큰**(팀 비밀번호 `APP_PASSWORD` 를 아는 사람이 사이트에서 발급 — 읽기),
그리고 고치게 하려면 그 공연(프로젝트)의 **편집 비밀번호**(사이트의 "편집 비밀번호 변경"으로 정한 것, 처음엔 `1234`).
토큰은 "누구인지"(기록에 남는 이름)와 읽기 권한이고, 편집 비밀번호를 대신하지 않는다.

**가장 쉬운 방법:** 사이트에서 그 공연을 열고 **편집 잠금을 해제한 뒤** 데이터 메뉴 → **에이전트 연결** 에서 토큰을 발급하면
사이트 주소·토큰·그 공연의 편집 비밀번호(`X-Edit-Key` 헤더)가 들어간 명령·설정이 나온다. 잠긴 상태에서 열면 편집 비밀번호 줄이 빠져
에이전트는 읽기만 한다. 비밀번호에 `$` `` ` `` `"` `\` `'` 같은 기호가 있어도 복사 버튼이 셸·TOML 용으로 알맞게 감싸 준다.

### 토큰 발급 (사이트에서)

1. 사이트 메뉴 **데이터 → 에이전트 연결** 을 연다(서버 모드에서만 보인다).
2. **토큰 발급** 칸에 쓸 사람 이름(예: `김민수`)을 넣고 **발급**. 이름은 1~40자, 이미 있는 이름(대소문자 무시)이나 기록에 따로 쓰는
   `관리자`·`사이트 비밀번호`·`브라우저`·`익명` 은 쓸 수 없다. 비교는 전각·반각과 대소문자를 무시하고(NFKC), 줄바꿈·제어 문자·폭 없는 공백 같은
   보이지 않는 문자가 든 이름은 거부한다.
3. 바로 아래에 그 사람의 토큰(`cue_…`)과 Claude Code 명령·Codex 설정이 나온다. **이 토큰은 지금 한 번만 표시된다** — 서버는
   토큰 원문을 저장하지 않으므로(해시만) 창을 닫으면 다시 볼 수 없다. **복사** 해서 그 사람에게 전한다. 잃어버렸으면 폐기하고 새로 발급한다.
   서버에 `ADMIN_KEY` 가 설정돼 있으면 발급·폐기 때 **관리자 키** 칸이 나온다 — 서버 관리자가 넣는다.
4. **발급한 토큰** 표에 이름·발급 시각·마지막 사용 시각이 나온다. **폐기** 를 누르면(한 번 더 눌러 확인) 그 토큰은 바로 `401` 로
   끊긴다. 다른 사람의 토큰과 팀 비밀번호는 그대로다.

**사이트 비밀번호로 연결** (접혀 있음): 토큰 없이 팀 비밀번호(`APP_PASSWORD`)를 그대로 넣는 방법. 기록에는 `사이트 비밀번호` 로 남고(누군지 구분되지 않음),
비밀번호를 바꾸기 전에는 끊을 수 없어 개인용으로는 권하지 않는다. 비밀번호가 없는 서버(로컬 개발)는 토큰 없이 연결되고 기록은 `익명`.

복사 버튼은 토큰·비밀번호에 `$` `` ` `` `"` `\` `'` 같은 기호가 있어도 셸·TOML 용으로 알맞게 감싼다(토큰은 영문·숫자·`-`·`_` 뿐이다).
손으로 쓰려면 아래 `<사이트>` 와 `<토큰>` 을 바꿔 넣는다. 셸 명령은 헤더 전체를 **작은따옴표**로 감싼다. 비밀번호(사이트·편집)를 넣을 때
비밀번호에 `'` 가 있으면 그 자리를 `'\''` 로 바꾼다.

### Claude Code

터미널에서 한 줄:

```sh
claude mcp add --transport http cue-sheet 'https://<사이트>/mcp' --header 'Authorization: Bearer <토큰>' --header 'X-Edit-Key: <편집 비밀번호>'
```

읽기만 시킬 거면 `--header 'X-Edit-Key: …'` 를 빼도 된다.

- Claude Code 를 열고 `/mcp` 를 입력하면 `cue-sheet` 가 **connected** 로 보여야 한다. 실패로 나오면 주소 끝의 `/mcp`,
  토큰 앞의 `Bearer ` (한 칸 띄움), 토큰이 폐기되지 않았는지를 확인한다.
- 기본은 지금 폴더(프로젝트)에서만 쓰인다. 어느 폴더에서나 쓰려면 `--scope user` 를 붙인다.
- 지우기: `claude mcp remove cue-sheet`

### Codex

`~/.codex/config.toml` 파일(없으면 만든다)에 추가:

```toml
[mcp_servers.cue-sheet]
url = "https://<사이트>/mcp"
http_headers = { "Authorization" = "Bearer <토큰>", "X-Edit-Key" = "<편집 비밀번호>" }
```

비밀번호(사이트·편집)를 넣을 때는 TOML 의 `"…"` 안에서 비밀번호의 `\` 를 `\\`, `"` 를 `\"` 로 쓴다.

Codex 를 다시 시작한 뒤 `/mcp` 로 `cue-sheet` 와 도구 6개가 보이는지 확인한다.

### 이렇게 말하면 된다

- "cue-sheet 에서 공연 목록 보여 줘" → `list_shows`
- "가을 정기공연 1부에서 멘탈 씬 구성 보여 줘" → `get_show`
- "탑햇 나오는 큐 찾아 줘" → `search_show`
- "Q11 다음에 '(테이블 정리)' 지문 넣고 무대 큐 달아 줘" → `edit_show`
- "방금 수정 취소해 줘" → `list_revisions` → `restore_revision`

토큰(또는 팀 비밀번호)만 있으면 읽기만 된다. 고치기(`edit_show`·`restore_revision`)는 그 공연의 편집 비밀번호가 있어야 하고,
없거나 틀리면 아무것도 저장하지 않고 "edit password required" 로 알려 준다. 편집 비밀번호를 바꾸면 위 설정도 바꿔야 한다.
편집 비밀번호가 다른 공연을 여러 개 고치게 하려면 헤더 대신 도구 인자 `editKey` 로 줄 수 있다(대화에 비밀번호가 남는다는 점에 주의).

에이전트가 저장한 수정·복원은 **연결한 사람의 이름(토큰 이름)** 으로 기록에 남는다 — "누가 Q12 바꿨어?" 하면 에이전트가
`list_revisions` 로 확인할 수 있다. 토큰은 그 사람의 비밀번호와 같으니 다른 사람과 나눠 쓰지 않는다.
음원 파일은 MCP 로 올리거나 지울 수 없다 — 웹 앱에서 한다.

## 설계

### 도구는 6개, 수정은 `edit_show` 하나

| 도구 | 하는 일 | 성격 |
|---|---|---|
| `list_shows` | 공연 목록 `{ id, title, rev, updatedAt, sceneCount, cueCount }` | 읽기 |
| `get_show { showId, view?, partId?, sceneId? }` | `outline`(기본): 한 줄에 하나씩 id·큐 번호·화자 이름·잘린 본문·큐 한 줄 요약(무대 큐는 소품 동작 포함) + 사람·소품·트랙 목록. `full`: 고른 파트/씬(또는 전체)의 JSON 그대로 | 읽기 |
| `search_show { showId, query }` | 대본·화자·큐(trigger·memo·무대/출연 내용·무대 큐 소품 이름·트랙 제목)·코멘트·씬 제목/세팅·사람·소품·공연 전 무대 소품·트랙에서 대소문자 무시 부분 일치. `Q12`/`12` 는 큐 번호. 최대 50개, id·위치·발췌 | 읽기 |
| `edit_show { showId, ops, dryRun?, expectRev?, editKey? }` | ops 를 원자적으로 적용 → 새 rev, 바뀐 내용 요약(새로 매긴 큐 번호 포함), 경고, 저장한 사람 `by`. `dryRun` 은 저장하지 않으므로 편집 비밀번호 없이도 된다 | 쓰기 (편집 비밀번호) |
| `list_revisions { showId }` | 저장 기록, 최신 먼저(맨 앞이 현재). 버전마다 누가(`by`)·어떤 경로로(`via`) 저장했는지, 복원이면 `restoredFrom` | 읽기 |
| `restore_revision { showId, rev, editKey? }` | 그 버전을 새 버전으로 저장(복원도 되돌릴 수 있음), 결과에 `by`. 이미 같은 내용이면 아무것도 안 함 | 쓰기 (편집 비밀번호) |

결과는 모두 사람이 읽는 텍스트와 `structuredContent`(JSON)를 함께 준다. 실패(없는 id, 틀린 값, 충돌 …)는 프로토콜 오류가
아니라 `isError: true` 결과로, **무엇을 어떻게 고치면 되는지** 문장으로 돌려준다(예: `"조예준" is a name, use id "p-yejun"`).
annotations: 읽기 도구는 `readOnlyHint`, `edit_show` 는 `destructiveHint`(지우기 가능), `restore_revision` 은
`destructiveHint` + `idempotentHint`(같은 rev 를 두 번 복원해도 결과가 같다).

**왜 도구 하나에 ops 배열인가.** `add_cue`·`move_scene` 같은 도구를 종류별로 만들면 20개가 넘고, 에이전트가 여러 번 호출하는 사이
일부만 반영된 상태가 저장된다. ops 배열이면 "문단 넣고 → 큐 달고 → 트랙 번호 바꾸기" 가 한 번의 원자적 저장이 되고(하나라도
틀리면 아무것도 안 바뀜), 저장 기록도 한 칸만 쓴다. 에이전트는 `get_show` 개요에서 id 를 보고 바로 op 를 만든다.

**개요는 싸게.** `cues/backstage-part1.json`(82문단·37큐) 기준 JSON 전체가 약 20,500자, 개요는 약 5,500자.
씬 하나만 보려면 `sceneId` 로 더 줄인다. 모든 필드가 필요할 때만 `view:"full"`.

### ops

모든 op 는 순서대로 적용되고, 끝난 뒤 (1) 새로 큐가 붙은 문단에 번호를 매기고 (2) show 전체를 `lib/validate.js` 의
`validateShow` 로 검사한다. **op 가 새로 만든 오류가 하나라도 있으면 전부 취소**한다. 원래 있던 오류(예: 사이트에서 사람을 지워
남은 화자 참조)는 막지 않는다 — 그렇지 않으면 그런 공연은 영영 고칠 수 없다. 오류 비교는 경로의 배열 번호를 뺀 모양 + 메시지로 한다.
알려진 한계: 같은 모양·같은 메시지의 오류가 원래 하나 있었는데 op 가 그것을 고치면서 **다른 곳에 같은 오류를 새로 만들면** 개수가 같아
새 오류로 잡지 못한다(드문 경우). 또 원래 있던 id 중복 오류는 메시지에 위치가 들어 있어, 그 항목을 옮기면 새 오류로 보여 막힐 수 있다.

| op | 형식 | 규칙 |
|---|---|---|
| set | `{ op:"set", id, kind?, fields }` | 준 필드만 바꾼다. `kind:"show"` 면 id 없이 `title`·`preShowSetup`·`revision`·`preShowProps`(배열 통째). 모르는 필드, `id`, `label`, `isCue`, 자식 배열(`items` 등), 트랙의 `fileName`/`fileKey` 는 거부 |
| add | `{ op:"add", kind, parent?, after?, data }` | `kind`: part·scene·item·cue·comment·person·prop·track. `parent`: scene→파트 id, item→씬 id, cue→문단 id, comment→씬 또는 문단 id (part·person·prop·track 은 없음). `after`: 형제 id / `"first"` / 생략·`null` = 맨 뒤. after 가 형제 id 면 parent 생략 가능 |
| remove | `{ op:"remove", id, kind?, force? }` | 안에 든 것까지 지운다. 화자·출연자·출연 큐가 가리키는 사람, 무대 큐·공연 전 무대가 가리키는 소품, 음향 큐가 쓰는 트랙은 사용처 목록과 함께 거부. `force:true` 면 지운다 |
| move | `{ op:"move", id, kind?, parent?, after? }` | 같은 단계 안에서 순서 바꾸기 또는 다른 부모로(큐를 다른 문단으로, 씬을 다른 파트로). parent 를 안 주면 지금 부모 안에서(after 가 다른 부모의 형제면 그쪽으로) |

- `kind` 는 서로 다른 종류에 같은 id 가 있을 때만 필요하다(그때는 오류가 알려 준다).
- **필드 형식.** 문자열 필드에 숫자를 주면 문자열로, 숫자 필드에 `"240"` 같은 숫자 문자열을 주면 숫자로 바꾼다. 그 밖은 거부.
  트랙 번호(`track.no`, 음향 큐 `sound.track`)는 1 이상의 정수(`sound.track` 은 미정이면 null). 필드 이름은 정해진 목록과
  정확히 같아야 한다(`constructor`·`__proto__` 같은 이름도 모르는 필드로 거부).
  열거형(`type`, `kind`, `dept`, `role`, `ch`, `action`, `move`, `status`)은 `docs/cue-format.md` 의 값만.
  사람 참조(`speaker`, `cast`, `cast.personId`)는 `people[].id` 만 — 이름을 주면 그 사람의 id 를 알려 주며 거부.
  소품 참조(`stage.props[].propId`, `preShowProps[].propId`)도 같게 `props[].id` 만. 소품 행에 propId 가 없으면 거부(브라우저 `saveCue` 와 같음).
- **얕은 합치기.** 큐의 `light`·`sound`·`stage`·`cast` 객체는 한 단계만 합친다: `{ sound: { level: 80 } }` 은 track·action·timeSec 을
  그대로 두고 level 만 바꾼다. 배열(`light.channels`, `stage.props`, `scene.cast`, show 의 `preShowProps`)은 통째로 바뀐다. 채널의 빠진 필드는 기본값
  (`ch:"front", action:"on"`, 나머지 null), 소품 행은 `action:"in"`, `at:""`. `dept` 를 바꾸면 이전 부서 내용은 버리고 새 부서 기본값에서 시작한다.
- **브라우저와 같은 정리.** action 문단은 화자를 지우고, 본문 첫 줄이 지문 머리(`(` `*` `—` 등, index.html `isActHead`)로
  시작하지 않으면 괄호를 씌운다(경고). `data.kind` 없이 본문 첫 줄이 `(` 로 시작하면 action.
- **표기 규칙** (`docs/cue-format.md` "표기 규칙"). 지문은 `(…)` 괄호 한 쌍 — `*`·`—` 시작, `)` 로 안 끝남, 괄호 안 괄호는
  편집기처럼 저장은 하되 `validateShow` 의 `action-format` 경고가 edit_show 결과에 나온다(op 가 새로 만든 경고만). 서버가 `*` 를
  괄호로 바꾸는 등 자동 고침은 하지 않는다 — 브라우저 편집기도 받는 값이고, 뜻을 바꾸지 않게 에이전트가 고치게 둔다. 음향 `level` 은 `volume`(없으면 100)·`fadeIn` 에서만 남긴다(index.html `saveCue`).
  `#rrggbb` 가 아닌 색은 `colorName` 으로 옮긴다(migrate). 큐가 바뀐 문단의 `isCue` 는 큐 유무를 따른다.
  내용 없는 큐(채널 없는 조명, 트랙 없는 음향, text 도 소품 동작도 없는 무대 …)는 저장하되 "채우거나 `status:"tbd"`" 경고.
- **새 항목.** id 는 브라우저 `uid()` 와 같은 접두어(`pt-` `s-` `i-` `q-` `c-` `p-` `pr-` `tr-`)로 만든다. 같은 호출의 뒤 op 에서
  가리키려면 `data.id` 를 직접 줘도 된다(`[A-Za-z0-9_-]{1,64}`, 쓰지 않은 값). 기본값은 브라우저가 새로 만들 때와 같다
  (씬 `type:"act"`, 사람 `role:"other"`, 무대 큐 `stage:{text:"", props:[]}`, 코멘트 작성자 `"익명"`, 트랙 `no` = 지금 최댓값 + 1). `data` 에 자식을 함께 넣을 수 있다:
  part.`scenes`, scene.`items`/`comments`, item.`cues`/`comments`.
- **트랙.** 항상 `no` 순으로 정렬된다(add 에 `after`, move 는 거부). `no` 를 바꾸면 그 번호를 쓰던 음향 큐의 `sound.track` 도
  함께 바뀐다. 겹치는 번호는 거부. 올린 음원이 있던 트랙을 지우면 파일은 서버에 남는다(경고).
- **사람 force 삭제.** 브라우저의 사람 삭제와 같이 씬 출연자 목록에서는 빼고, 대사 화자·출연 큐는 그대로 둬 사이트에
  "(삭제된 사람)" 으로 보인다(경고 한 줄로 개수를 알려 줌).
- **소품 (show v6).** `props[]` 는 사람처럼 `kind:"prop"` 의 add/set(name·note)/remove/move 로 고친다. force 삭제는 브라우저 소품
  삭제와 같이 `preShowProps` 에서는 빼고, 무대 큐의 소품 행은 그대로 둬 "(삭제된 소품)" 으로 보인다(validateShow 경고).
  `preShowProps` 는 항목 id 가 없어 `set kind:"show"` 의 배열 통째 교체만 된다.
- **v5 → v6.** v5 공연에 op 를 적용하면 사이트가 불러올 때(migrate)처럼 `version:6`, 빈 `props`·`preShowProps`, 무대 큐의
  빈 `stage.props` 를 붙여 저장한다. 다른 값은 바꾸지 않는다(v4 이하는 그대로 두고 사이트의 변환에 맡긴다).

### 큐 번호

`item.label`(화면의 Q12)은 `lib/labels.js` 가 매긴다. index.html 의 "큐 번호" 구간(`relabel`·`fillLabels` 등)을 그대로 옮긴 것이고
`test/labels.test.js` 가 index.html 의 함수를 직접 떼어 와 같은 결과인지 대조한다. 규칙: 늘 1, 2, 3 … 대본 순서대로, 큐가 없는 문단은 `null`
(소수 번호 없음). op 를 적용한 뒤 어긋나 있으면 전부 다시 매긴다 — 큐 추가·삭제·이동, 큐 달린 문단의 이동·삭제 뒤에는 그 뒤 번호가 바뀐다.
사이트도 편집을 저장할 때 같은 규칙으로 다시 매긴다. 읽기(`get_show`·사이트에서 열기)는 번호를 바꾸지 않는다.
`edit_show` 결과의 `labels` 는 번호가 바뀐 문단 `{ id, label, was }` 목록이다. 번호는 바뀌므로 op 에서는 id 로 가리키고, `label` 은 set 으로 바꿀 수 없다.

### 동시 편집

- 서버 안의 쓰기는 프로젝트마다 하나의 큐로 직렬화된다(다른 프로젝트끼리는 기다리지 않는다). `edit_show` 는 `store.update(id, fn)` — **쓰기 큐 안에서 최신 버전을 읽어** ops 를
  적용하고 rev 를 올린다. 그래서 브라우저 저장과 MCP 수정이 동시에 와도 한쪽이 다른 쪽을 모르고 덮어쓰는 일은 서버에서는 없다.
- `expectRev` 를 주면 그 rev 일 때만 저장한다(개요를 읽은 뒤 누가 저장했으면 "다시 읽고 하라" 는 오류). 안 주면 최신 버전에
  op 를 적용한다 — op 가 id 로 가리키므로 그 사이 다른 곳이 바뀌었어도 대개 그대로 맞다.
- **브라우저 쪽: 409 자동 병합 (2단계 a, 구현됨).** 브라우저는 5초마다 `If-None-Match` 로 폴링하고, 고치던 내용이 없으면 MCP 수정을
  바로 받아 온다. **그 사이 브라우저에 저장 안 된 편집이 있으면** 다음 저장이 409 가 되는데, 이때 선택 바를 바로 띄우지 않고 id 단위로
  합친다. 예전에는 "서버 버전 / 내 버전" 둘 중 하나를 골라야 해서 "내 버전" 을 고르면 MCP 수정이 사라졌다.
  - 병합은 `lib/merge.js` 의 `mergeShows(base, local, remote, { relabel })` (Node 는 `require`, 브라우저는 서버 모드로
    시작할 때(`serverBoot`, 프로젝트를 열기 전) `/lib/merge.js` 를 `<script>` 로 동적으로 읽어 `window.CueMerge` — 빌드 없음. 로컬 모드
    (claude.ai 아티팩트·`file://`)에서는 외부 스크립트를 못 읽으므로 요청하지 않는다). 기준(`Srv.base`)은 마지막으로
    서버와 맞춘 내용 — 열 때, 저장(PUT) 성공 때(보낸 그 내용), 서버 내용을 반영할 때(폴링·"서버 버전 사용"·버전 복원·잠금 "버리기") 바뀐다.
    세 값 모두 `migrate()` 를 거쳐 넘긴다.
  - **충돌 없음** → 합친 것을 이 기기 내용으로 삼아 화면에 반영(서버 변경 반영과 같은 경로라 커서·선택·편집 중인 씬은 그대로)하고,
    `baseRev` 를 서버 rev 로 바꿔 다시 저장한다. "다른 기기의 변경과 합쳤습니다" 알림. 다시 저장해도 또 409 면 3번까지 반복하고, 그다음은 선택 바.
  - **입력 중이면 미룬다** — 포커스가 모달·입력칸에 있거나, 대본 편집기에서 고치던 씬을 서버도 고쳤으면 화면을 바꾸지 않고 저장을 멈춘다
    (상단 "저장 대기 — 입력을 마치면 다른 기기 변경과 합칩니다"). 그동안의 변경은 이 브라우저에 백업한다. 포커스가 빠지면 폴링으로 최신 서버
    내용을 받아 다시 합친다.
  - **폴링이 먼저 보면 미리 합친다** — 이 기기 변경이 대기 중인데(저장 직전·재시도 중) 폴링이 새 rev 를 보면 저장을 기다리지 않고 같은 방식으로
    합친다. 충돌이 있으면 여기서는 건드리지 않고 저장의 409 처리에 맡긴다.
  - **충돌 있음** → 선택 바에 "자동으로 합치지 못한 곳 N곳" 과 목록(최대 5줄, `conflicts[].text` 예:
    `1부 › 예준 인사 멘트 › 「안녕하세요…」 — 본문: 양쪽에서 다르게 고침`)을 보여 주고 고르게 한다: **서버 버전 사용** / **내 것으로 덮어쓰기**
    (MCP 수정이 사라짐 — 기록에는 남아 복원 가능) / **충돌 항목만 서버 것으로, 나머지는 병합**(누를 때 지금 내용으로 다시 합친다).
  - **병합하지 않는 경우** — 병합 모듈을 못 읽었거나(파일로 연 index.html 옆에 `lib/` 가 없음 등), 서버 원본(migrate 전)에 id 없는 항목이
    있으면(서버는 id 를 강제하지 않는다 — migrate 가 받을 때마다 다른 임시 id 를 만들어 같은 항목이 둘로 보이므로. `hasAllIds`; 브라우저가 한 번
    저장하면 id 가 붙는다) 목록 없는 예전 선택 바. 서버 show 의 `version` 이 이 화면보다 높으면 합치지도 덮어쓰지도 않고 "새 버전이 있습니다 —
    새로고침" 바(`markOutdated`)로 간다.
  - 서버 내용(또는 병합 결과)으로 바꿀 때는 `localReplaced()` 한 곳에서 이 기기 전용 되돌리기 기록을 비운다 — "마지막 삭제 되돌리기"(show
    통째 스냅샷이라 남기면 합쳐진 에이전트 수정까지 되돌린다)와 편집기 되돌리기(부분 반영 때 편집 중인 씬 것만 남김).
  - 서버에 아직 있는 항목은 "서버 쪽으로 정한" 결과에서 사라지지 않는다 — 이 기기가 서버에서 지운 문단으로 큐를 옮겼으면 그 큐는 서버 쪽
    원래 자리로 돌아간다.
  - 401(사이트 비밀번호)은 `api()` 가 다시 묻고 같은 요청을 다시 보내고, 403(편집 비밀번호)은 "편집 잠김" 으로 저장을 멈춘다 — 둘 다 충돌로 보지 않는다.
  - 그래도 에이전트 instructions 의 "큰 수정 전에는 사용자에게 알린다" 는 그대로 둔다(같은 문단을 동시에 고치면 여전히 묻는다).
  병합 규칙:
  - 사람·소품·트랙·파트·씬·문단·큐·코멘트는 종류+id 로 맞춘다. **필드 단위** — 한쪽만 바꿈 → 그쪽, 같게 바꿈 → 그대로, 다르게 바꿈 → 충돌.
    큐의 부서 객체(`light`·`sound`·`stage`·`cast`)는 안쪽 필드까지 나눠 보고, 배열(`light.channels`, `stage.props`, show 의
    `preShowProps`)은 통째. **문단 본문(`text`)도 통째** — 글자 단위로 섞지 않는다. 씬 출연자(`cast`)는 id 집합으로 합친다(충돌 없음).
  - **추가**는 양쪽 모두 남는다. **삭제**: 다른 쪽이 그대로면 삭제. 다른 쪽이 그 항목이나 **그 안의 어느 것이라도**(자식 추가·수정·옮겨 넣기)
    고쳤으면 충돌 — 대본 문단·큐는 내용이 있는 것이라 조용히 지우거나 조용히 되살리지 않는다. 충돌은 지워진 것들 중 맨 위 항목 하나로
    센다(씬을 지웠으면 씬 하나). 서버 쪽으로 정하면: 서버가 지운 것은 지운 채(그 아래 이 기기 추가분도 버림), 서버가 고친 것은 그 항목 아래
    전체를 서버 내용으로 되살린다. 순서만 바꾼 것은 고친 것으로 치지 않는다.
  - **다른 부모로 옮기기**(큐를 다른 문단으로, 씬을 다른 파트로)는 "부모" 필드를 바꾼 것 — 내용 수정과는 합쳐지고, 양쪽이 서로 다른 곳으로
    옮기면 충돌.
  - **순서**: 서버 순서에서 시작해, 이 기기에서 새로 넣거나 옮긴 항목을 이 기기 목록에서 가장 가까운(서버가 옮기지 않은) 이웃 바로 뒤에,
    앞쪽 이웃이 없으면 뒤쪽 이웃 앞에, 둘 다 없으면 맨 뒤에 끼운다. 결정적이다. 같은 항목을 양쪽이 옮겼으면 서버 위치(충돌 아님).
    트랙은 항상 `no` 순. 양쪽이 같은 자리에 넣으면 이 기기 것이 앞에 온다.
  - **큐 번호(`label`)·`isCue` 는 충돌로 치지 않는다.** 병합 뒤 `relabel`(lib/labels.js, 브라우저는 index.html 의 같은 함수)로
    늘 1부터 연속으로 다시 맞춘다 — 양쪽이 각자 맨 뒤에 큐를 달아 둘 다 Q33 이었으면 병합 순서대로 Q33·Q34 가 된다. 그래서 이 기기나
    서버에서 본 번호가 병합 뒤 바뀔 수 있다. `isCue` 는 큐가 있으면 true.
  - 그 밖의 필드는 이름을 가리지 않고 3-way 로 합친다 — 코멘트 `snapshot`(v7) 같은 새 필드도 그대로 남는다.
  - show 의 `id`·`version`·`updatedAt` 은 서버 것. `revision`(판 표시)은 사람이 쓰는 값이라 한쪽만 바뀌면 그쪽, 둘 다 바뀌면 서버 것(충돌 아님).
  - 병합 뒤 **트랙 번호가 겹치면** 충돌(양쪽이 각자 새 트랙을 BGM 8 로 만든 경우). 서버 쪽으로 정하면 이 기기 트랙을 맨 뒤 번호로 옮긴다.
  - id 가 없거나 겹치는 항목이 있으면 `ok:false`.
  남은 한계: 의미까지는 보지 않는다 — 한쪽이 트랙 번호를 바꾸며 음향 큐를 고쳤는데 다른 쪽이 옛 번호로 새 음향 큐를 달면 그 큐는 옛 번호를
  가리킨 채 남는다. 사람·소품을 지운 쪽과 그 사람·소품을 새로 참조한 쪽이 합쳐지면 "(삭제된 사람/소품)" 참조가 생긴다(검증 경고, 기존 동작과
  같음). 같은 문단 본문을 양쪽이 고치면 글자 단위로는 합치지 않고 충돌로 묻는다. 테스트: `test/merge.test.js`(backstage-part1 + `applyOps`
  실제 흐름, 무작위 60회 포함). 브라우저 흐름(409 → 병합 → 재저장, 입력 중 미룸, 충돌 바)은 자동 테스트가 없다 — headless 브라우저로 손으로 확인.

### 기록 (되돌리기)

- 쓰기 직전 버전을 `DATA_DIR/shows/<id>/history/<rev>.json`(`{ rev, updatedAt, show[, restoredFrom] }`)으로 남긴다. **최근 100개**
  (env `HISTORY_KEEP`). 예전 위치 `shows/<id>.history/` 는 서버가 시작할 때 이리로 옮긴다. 웹 앱의 "버전 기록 · 복원"과
  HTTP `GET /api/shows/:id/history`·`POST …/restore` 도 같은 기록이다.
- MCP 수정(`update`)과 복원(`restore`)은 매번 남긴다. 브라우저 저장(PUT)은 몇 초마다 오므로 솎는다: 직전 쓰기가 PUT 이 아니었을
  때(= MCP 수정·복원 직후, 서버 재시작 후 첫 PUT) 또는 마지막으로 남긴 지 10분이 지났을 때만. 그래서 MCP 수정 직전·직후 상태는
  브라우저 편집이 이어져도 남는다.
- 복원은 그 버전의 내용을 **새 rev 로 저장**하는 것이라 복원도 기록에 남고 되돌릴 수 있다. 음원 파일은 기록에 없으므로,
  복원한 버전의 트랙이 그 사이 지워진 음원을 가리키면 그 트랙의 `fileKey`·`fileName` 을 비우고 경고로 알린다(웹 앱에서 다시 올린다). 프로젝트를 지우면 기록도 프로젝트 폴더째 휴지통(`DATA_DIR/trash/`)으로 옮겨지고, 되살리면 기록도 돌아온다.
  복제는 기록을 가져가지 않는다.

### 프로토콜·SDK

- 공식 MCP TypeScript SDK v2: `@modelcontextprotocol/server` 2.4.0 + `@modelcontextprotocol/node` 2.1.2 (`engines: node >=20`).
  CJS 빌드도 들어 있어 `require` 로 쓰고, `/mcp` 첫 요청 때 불러온다 — SDK 가 없으면 `/mcp` 만 `503 mcp_unavailable`,
  나머지 서버는 그대로. 테스트용 클라이언트 `@modelcontextprotocol/client` 는 devDependency.
- `createMcpHandler(factory, { legacy: 'stateless', responseMode: 'json' })` + `toNodeHandler`. 요청마다 새 `McpServer` 를 만드는
  상태 없는 방식(서버에 세션 없음). 2026-07-28 개정판 클라이언트는 기본 경로로, 2025 개정판 클라이언트(현재의 Claude Code·Codex
  등)는 `legacy: 'stateless'` 대체 경로로 같은 도구를 받는다. 세션이 없으므로 GET(SSE 대기)·DELETE 는 `405`.
- 입력 스키마는 zod 없이 JSON Schema(`fromJsonSchema`)로 적었다. 스키마에 안 맞는 인자는 SDK 가 `isError` 결과로 돌려준다.

### 인증

**편집 비밀번호.** 쓰기 도구는 `/api` 의 쓰기와 같은 검사(`server.js` 의 `editCheck`, 해시는 `shows/<id>/auth.json`)를 거친다.
키는 도구 인자 `editKey` 가 있으면 그것, 없으면 요청 헤더 `X-Edit-Key`(UTF-8 그대로 또는 URL 인코딩). 틀린 키는 `/api` 와 같은
실패 제한(IP+프로젝트당 1분 10회, 같은 카운터)을 받는다. 도구 처리기는 `AsyncLocalStorage` 로 지금 HTTP 요청의 헤더·IP 를 본다.
검사 함수가 없으면 쓰기를 막는다(fail-closed). 읽기 도구(`list_shows`·`get_show`·`search_show`·`list_revisions`)는 아래 사이트 인증만.

**사이트 인증** — 누구인지. 두 가지를 받는다 (`server.js` 의 `mcpActor`):

- **사이트 비밀번호** (`APP_PASSWORD`): `/api` 와 같은 검사(`authed`) — `Authorization: Bearer <APP_PASSWORD>`, `X-App-Key`(URL 인코딩 가능),
  `?key=` 중 하나. 헤더에 한글 비밀번호를 UTF-8 그대로 실어 보내는 클라이언트도 통과한다. 기록에는 `사이트 비밀번호`.
- **사람별 토큰** (`lib/tokens.js`): `/mcp` 에서 `Authorization: Bearer cue_…` 로만. `X-App-Key`·`?key=` 로는 받지 않고(주소는 로그에
  남기 쉽다), `/api` 에서는 어떤 방식으로도 받지 않는다 — 토큰으로는 MCP 로 읽기(그리고 편집 비밀번호를 함께 줄 때 MCP 쓰기)만 되고, 프로젝트 삭제·음원·토큰 관리는 안 된다. 토큰은 편집 비밀번호를 대신하지 않는다 — 사이트 비밀번호만 있으면 누구나 토큰을 발급할 수 있으므로, 토큰이 편집 권한을 주면 프로젝트별 편집 비밀번호가 무력해진다.
  기록에는 토큰 이름.

틀리거나 없으면 `401 {"error":"unauthorized"}` + `WWW-Authenticate: Bearer`. 401 때 길이를 아는 작은 본문(≤64KB)만 비우고, 길이를 모르거나 큰 본문은
읽지 않고 응답 뒤 연결을 닫는다(`/api` 도 같음). 서버의 `keepAliveTimeout` 은 65초(프록시 유휴 시간보다 길게). `APP_PASSWORD` 가 없으면 `/api` 처럼
인증 없이 열리고(로컬 개발용) 토큰 관리 API 는 `404 tokens_disabled`. OAuth 는 없다.

**토큰 저장.** `DATA_DIR/tokens.json` 에 `[{ id, name, hash, createdAt, lastUsedAt }]`. 토큰은 `cue_` + 무작위 32바이트 base64url 이고,
원문은 발급 응답(`POST /api/tokens`)에서 한 번만 돌려준 뒤 버린다 — 파일에는 sha256 hex 만. 쓰기는 `store.js` 처럼 임시 파일 → rename,
한 큐로 직렬화. 파일은 이 프로세스만 쓰므로 시작할 때 읽어 메모리에 두고, 깨져 있으면 서버가 시작하지 않는다(빈 목록으로 덮어써
토큰이 사라지지 않게). `lastUsedAt` 은 토큰마다 1분에 한 번만 파일에 쓴다.
**조회가 시간 차이로 새지 않는 이유:** 받은 문자열의 sha256 으로 Map 을 찾는다. 조회 시간이 달라져도 드러나는 건 "입력의 해시가
저장된 해시와 얼마나 닮았나" 뿐이고, 해시에서 토큰을 되돌리거나 원하는 해시 접두어가 나오는 입력을 고를 수 없다(sha256 역상 저항).
토큰 원문을 한 글자씩 비교하는 경로가 없으므로 `timingSafeEqual` 이 필요 없다. 사이트 비밀번호 비교는 지금처럼 `timingSafeEqual`.

**관리 API** (README 의 API 표): `GET /api/tokens`(해시 없이 목록, 사이트 비밀번호), `POST /api/tokens {name}` → `201 { token, id, name, createdAt }`,
`DELETE /api/tokens/:id`. 폐기는 요청을 받는 즉시(쓰기 대기열을 기다리기 전에) 메모리에서 막으므로 바로 다음 요청부터 `401`.
파일 쓰기가 실패하면 `500 save_failed` — 그 서버 프로세스에서는 계속 막혀 있고 목록에도 남지만, 파일에는 아직 있어 **다시 폐기하거나 다른 토큰 쓰기가
성공하기 전에 재시작하면 그 토큰이 다시 통한다**(실패를 알려 주는 이유). 메모리는 파일 쓰기가 성공한 뒤에만 바뀐다.
**`APP_PASSWORD` 를 바꿔도 이미 발급한 토큰은 그대로 통한다** — 토큰은 사이트 비밀번호와 따로 저장된다. 사람을 내보낼 때는 그 사람의 토큰을 따로 폐기한다.
**`ADMIN_KEY` 가 설정된 서버는 발급·폐기에 관리자 키(`X-Admin-Key`)도 필요하다** (편집 비밀번호 초기화와 같은 검사·같은 실패 제한, `server.js` 의 `needAdmin`).
토큰 이름이 기록의 "누가" 이므로, 팀 공용 사이트 비밀번호만 아는 사람이 남의 이름으로 발급하거나 남의 토큰을 폐기하지 못하게 하려는 것.
`ADMIN_KEY` 가 없는 서버는 예전처럼 사이트 비밀번호로 발급·폐기한다(호환). 에이전트 연결 패널은 `403 admin_forbidden` 을 받으면 관리자 키 칸을 띄운다(키는 저장하지 않음).
지운 공연은 휴지통(`DATA_DIR/trash/`)으로 옮겨져 `shows/` 에 없으므로 MCP 의 모든 도구에서 "없는 공연" 이다. 되살리면 기록(by·via 포함)과 함께 돌아온다. `tokens.json` 은 휴지통과 무관.

**누가 고쳤는지 (기록의 by·via).** 기록은 하나(`store` 의 레코드·스냅숏, `/api/shows/:id/history` 와 `list_revisions` 가 같이 읽는다)라 by·via 도 거기 한 곳에만 있다. 공연 파일과 기록 스냅숏은 `{ rev, updatedAt, by, via, show[, restoredFrom] }` — `by`·`via` 는 **그 버전을 만든 쓰기**의
사람과 경로다. `by`: 토큰 이름 | `사이트 비밀번호` | `브라우저` | `익명`(비밀번호 없는 서버의 MCP), `via`: `mcp`(edit_show) | `restore`(restore_revision) |
`browser`(웹 앱의 저장·새 프로젝트·복제 — `/api` 쓰기). 웹 앱의 버전 복원(`POST /api/shows/:id/restore`)은 `브라우저`·`restore`. 편집 비밀번호는 프로젝트 공용이라 사람을 구분하지 못해 웹 앱 쓰기의 이름은 모두 `브라우저`.
이 필드가 생기기 전 파일에는 없고 `list_revisions` 에서 `null` 로 보인다(형식은 그대로 호환). 인증한 신원은 `server.js` 가
`mcp(req, res, actor)` 로 넘기고, `lib/mcp.js` 가 `req.auth` → SDK `authInfo` → 요청마다 부르는 factory 의 `ctx.authInfo` 로 받아 그 요청의
`McpServer` 에 묶는다(상태 없는 방식이라 요청 사이에 섞이지 않는다 — `test/tokens.test.js` 가 두 토큰 동시 수정으로 확인).
